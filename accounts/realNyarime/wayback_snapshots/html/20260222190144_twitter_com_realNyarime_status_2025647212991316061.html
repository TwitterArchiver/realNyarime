基础概念：上下文与缓存计费（最容易被忽略的部分）上下文（Context）： 200k上下文 = 模型能记住约20万token的内容，超了就记不住，表现会开始“注意力分散”、效果变差。 1M上下文 = 能处理更多内容，模型整体会显得更聪明、更连贯。缓存计费请参考Claude官方API规则，下面是我昨天的真实使用数据（按5分钟缓存写入 + 标准定价，基于Opus 4.6规则计算，实际会混用Sonnet等，略有差异，但规则一致）：输入输出量少、价格贵，但占比不高；缓存部分量大、单价低，却占据了大头。
真正的API计费里，缓存处理非常关键——既影响价格，也影响模型智力。
缓存命中：你创建了多少缓存，本来的输入输出有多少在有效时间内命中了缓存，命中的部分就走低价缓存计费。
缓存时间：官方默认5分钟，5分钟内没命中就释放、重新算新建缓存。目前支持1小时缓存的使用体验最佳。

为什么中转经常贵得离谱？
很多中转几乎没有缓存（或缓存时间极短），每次请求都在新建缓存 → 计费直接翻倍 + 上下文不连贯 → 模型“降智”。而官方Max账号因为缓存命中率高，用起来反而“很耐用、很便宜”。这就是差距。市面常见渠道区别总结（经验之谈，仅供参考）：
逆向渠道（Kiro、反重力等）
优势：便宜。 缺点：表现力极差、严重降智。
原因：逆向API自带软件专属提示词（上下文污染），几乎无缓存（轮询随机池），计费贵、思考不连贯。属于“吃糟糠”的级别。
AWS Bedrock / Azure / GCP 自部署模型
本质是Anthropic允许在大厂云上部署正品模型，按API Key计费。
一对一专属部署：团队永远用同一个模型，完整上下文 + 1h缓存，表现和官方几乎无差别。
缺点：贵（企业大户能谈到1¥≈1$，普通购入3.5¥+）。体验最好。
多对多API Key池：用多个IAM账号轮询，正品模型、支持1M上下文，但几乎无缓存 → 略微降智 + 计费翻倍。价格便宜（0.1~0.3毛一刀）。 还有openrouter、zenmux等类似产品，原理相近，我还没全试。
自开Max账号
效果最好，但不支持1M上下文、价格贵、有随机封号风险。如果做号池，也要注意多账号路由导致的缓存问题（原理同上）。
