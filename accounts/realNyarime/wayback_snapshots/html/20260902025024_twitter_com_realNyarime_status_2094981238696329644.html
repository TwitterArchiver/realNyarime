从PVE8升级到PVE9的指引
昨日PVE7.x身份绕过（预身份验证 RCE）被揭露后，同时发现生产环境里的PVE8.4也存在这个问题，因此对生产环境的所有VM停机并升级宿主机PVE版本至最新的9.2.11，不过看评论区说建议还是把8006端口关上、设置白名单。



我的生产环境是PVE 8.4.0（内核 6.8.12-9-pve），按论坛里的说法，8.x（含 8.4）也有被勒索的报告，且 PVE 8 已 EOL，之后基本不会再有正式安全更新。不过好在，自查了一下root@pam还没中招，看来黑阔对我的服务器没有兴趣。

设计的，务必再给pve备一个screen（或tmux），升级过程中SSH会偶尔断开一下，以便能及时恢复会话。如果升级过程有报错等问题，可以配AI在旁边记录升级过程，以便弄炸了还能回退。

简单升级

如果你想手动升级，请从下文阶段1开始操作。做好准备工作后，执行pveversion。如果还是 8.4.0，说明上次 apt dist-upgrade 没跑完，重跑一次。然后把脚本传到PVE上，赋权执行：



如果出现报错，可以尝试使用本脚本修复：./pve8to9.sh fix

它会逐项问你：

移除 systemd-boot 元包 → 选 y（这是唯一的 FAIL）

安装 amd64-microcode → 选 y

LVM autoactivation 迁移 → 你是纯本地 local-lvm，选 y 或 n 都行

停用审计 socket → 选 y，减少升级时刷屏

然后使用./pve8to9.sh preflight复查，确认 FAILURES: 0后，就可以放心做升级了。升级前最好是手动去关停虚拟机，因为有些VM并没有配置QEMU Guest Agent，没法优雅关机只能切断电源了。不过我知道你很懒，那就接着做吧：



再次强调，在SSH下一定要 tmux（或 screen）。断线不会中断 dist-upgrade。 不要用 Web UI 里的 noVNC 控制台执行升级，因为在升级过程会重启 pveproxy，把你踢掉。

阶段1：升级到最新8.4

阶段2：跑官方检查并清掉 FAIL

执行pve8to9 --full，标是 FAILURES 为 0。下面是常见项的处理方式。

FAIL：systemd-boot 元包已安装

Debian 13 把 systemd-boot 拆成了 systemd-boot-efi（EFI 二进制）、 systemd-boot-tools（bootctl）和 systemd-boot 元包（含升级钩子）。 PVE 的引导由 proxmox-boot-tool 管理，元包的钩子会干扰引导相关包的升级。



唯一例外：你手动把 systemd-boot 配成了引导器。 若 systemd-boot-efi / systemd-boot-tools 仍被需要，pve8to9 会另行提示。

WARN：检测到运行中的客户机

升级过程中客户机继续跑，有文件系统或数据库损坏风险。全部关机：



清单保存在 /var/lib/pve8to9-helper/running-guests.txt，升级后可原样拉起。

WARN：缺少 CPU 微码包

需要 apt 源里带 non-free-firmware 组件。不阻塞升级，但建议装上。

想回退?

没有真正的原地降级路径。 唯一可靠的回退是从备份恢复。 这也是阶段 0 强调「备份必须验证过」的原因。

rollback-repos 只能还原 apt 源配置，不能撤销已安装的包。
